# choom v0.0.4 release notes

Scope: the 7 issues milestoned `v0.0.4` (#39, #43, #47, #60, #79, #81, #84) plus the other PRs
milestoned `v0.0.4` that don't close an issue directly. All landed on the `release/v0.0.4` branch;
they become visible on `main`/PyPI once that branch merges via #101.

## TUI features

**Automatic link detection** (#39, PR #93)
Saving a document or a task's body — in the editor or via `/ai` — now turns any bare `http://` or
`https://` URL in the text into a real CommonMark inline link (`[<url>](<url>)`), so it renders as
a clickable link everywhere instead of dead text. The conversion only happens on those two save
gestures; mirror reconcile-on-open, `choom links heal`/`check`, `note new`/`meeting new`
frontmatter, and a task's one-line description are all left untouched by construction. New pure
functions `format_bare_urls` and `map_cursor_offset` land in `choom.core.links`; seven
length-preserving masks (frontmatter, fenced/inline code, HTML comments, existing links/images,
autolinks/raw HTML) keep the conversion from touching anything it shouldn't.

**Completed tasks move out of the open list** (#43, PR #96)
A completed task's record now moves out of `tasks.md` into a per-day file under
`tasks/done/YYYY/MM/`, so an assistant (or a human) reading the open list no longer pays for a
year of finished work every time it's read. Un-completing a task moves it back. `tasks.md` stays
the canonical address of the collection — a mirror elsewhere is recognized by its `#task_<id>`
fragment, never by path, so a moved record breaks no existing document link. The move is a splice
at the record's exact span (never a delete-and-recreate, which would mint a new id and orphan every
mirror), with the destination always written before the source so the only reachable failure is a
duplicate line, not a dropped one.

**Delete a task from the editor with `ctrl+t`** (#79, PR #91)
With the cursor on a task's line in the document editor, `ctrl+t` removes that task from both the
document body and the task list, after one confirmation. The removal is a splice at a recorded
character span (never a re-render, never a text match), so blank lines and unrelated content
around it survive untouched. If the task record can't be found but the rest of the task list reads
cleanly, it falls back to removing just the line; if the task list itself has an unreadable line,
it refuses and writes nothing rather than guessing. Undo restores the line without discarding the
buffer's prior undo history.

**Terminal tab reflects the active workspace** (#47, PR #90)
choom now sets the terminal tab/window title to `choom — <workspace name>` once at startup and
restores whatever was there before on every exit path it can observe (clean quit, quit-through-
discard-confirmation, an unhandled exception, `KeyboardInterrupt`) — useful for telling apart
several long-lived sessions in a crowded tab strip. The title reflects only the workspace name and
is set once; it does not track the active collection, month, or filter as they change. Works on
Windows too, via a standard-library `ctypes` call that enables virtual terminal processing before
the TUI takes over the console. Setting or restoring the title never raises to the user and never
changes the exit code, even on a non-TTY stdout or an unsupported terminal.

**Vertical layout for narrower windows** (#81, PR #97)
`/config view vertical` rearranges the list screen for a half-width window: the collection bar
stays across the top, the scope list and record list sit side by side in an upper band, the
preview/inline-edit region moves to a full-width band beneath them, and the status bar stays at the
bottom. `/config view horizontal` restores the existing three-panes-across layout. The choice
persists across sessions, stored in new per-user local state (`choom.core.preferences`) rather than
the shared workspace config — a view orientation is a property of one person's monitor, so it can't
live in a file that syncs to a colleague's screen. On a terminal too short for both bands to meet
their minimums, choom degrades to horizontal for as long as the terminal stays that short, and
recovers automatically on resize; opening the command bar or link picker can never itself flip the
layout. Default remains horizontal.

## Maintenance / CI

**Least-privilege permissions on `publish.yml`'s test job** (#60, PR #89)
CodeQL flagged the `test` job in `.github/workflows/publish.yml` for not scoping down the
`GITHUB_TOKEN`. It now gets `contents: read`, matching the pattern already used elsewhere in that
workflow and in `tests.yml`/`release-dry-run.yml`.

**Performance-test flakiness on shared CI runners** (#84, PRs #88 and #95)
Every wall-clock-budget assertion in `tests/performance/` had flaked, one at a time, across several
release cycles, each fix landing only on the specific test that had just gone red. #88 went
through all seven flagged assertions at once and converted the ones with no deterministic
work-done proxy to best-of-5 sampling. When that still wasn't enough on a uniformly slow runner
(all five samples over budget on one CI run), #95 split `tests/performance/` out of the ordinary
`test` matrix job into its own `performance` job — gated on Python 3.13 only, selected by
`pytest`'s existing `performance` marker — so a slow-runner flake there no longer blocks or gets
conflated with ordinary PR checks. This isolates the flake; it does not make the underlying
wall-clock budgets themselves immune to a slow runner, which remains open as the rest of #84.

## Internal tooling (not part of the released product)

A handful of other PRs milestoned `v0.0.4` are process/orchestration improvements to this repo's
own `delamain` (autonomous delivery) and `regina` (product-owner) skills, plus one documentation
correction:

- **`delamain` resumability** (PRs #92, #94, #98) — the orchestrator only wakes when a subagent
  finishes, so a turn that ends with nothing in flight used to stall a run until a human noticed
  (it happened twice this cycle, once for over six hours). These PRs add explicit rules against
  reporting an action before confirming it happened, make `/loop 20m /delamain <milestone>` a
  supported resumable re-entry point instead of restarting the whole skill from Step 1, and require
  labelling any PR merged on the orchestrator's own authority with `delamain` for audit purposes.
- **`regina` renamed from `product-owner`** (PR #99) — same skill, new name to match `delamain`'s
  naming, plus a retuned refinement bar (a "Scope & decisions" section covering in/out of scope
  and one-line decisions) for issues that will be handed to an unsupervised `delamain` run with no
  human to ask when a spec agent hits ambiguity.
- **T041 correction** (PR #100) — a hand-verification task in #43's `tasks.md` had been marked
  done by a blanket find-and-replace rather than actually performed; corrected to reflect what was
  really verified and what's deferred to the pre-release gate.

These don't change anything about the `choom` CLI/TUI a user runs and aren't reflected in
`README.md`'s feature list.
