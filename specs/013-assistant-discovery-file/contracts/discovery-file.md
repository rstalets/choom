# Contract: the discovery file

**Feature**: 013-assistant-discovery-file

What choom writes into another program's profile directory. This is the feature's only outward-
facing artifact, and the only file choom writes outside the workspace.

---

## Locations

| Assistant | Path | Read by that tool when |
|---|---|---|
| `claude` | `<profile>/.claude/skills/choom/SKILL.md` | every session, any working directory |
| `copilot` | `<profile>/.copilot/instructions/choom.instructions.md` | every session, all repositories |

`<profile>` is `Path.home()` — `%USERPROFILE%` on Windows. Missing directories are created
(FR-011). Both relative paths are short enough to be irrelevant to the Windows 260-character limit.

## Shape — `claude`

```markdown
---
name: choom
description: <one line: what choom is, and that this workspace holds the user's notes>
---

# choom

<one line: what choom is>

The user's choom workspace is at:

/absolute/path/to/workspace

Read `AGENTS.md` in that directory before creating or changing anything in it. It documents
the commands, the layout, and the file format this tool expects.

<!-- Generated by choom (`choom config assistant`). Rewritten on every run; edits are lost. -->
```

## Shape — `copilot`

The same body under a plain `# choom` heading, without the frontmatter. Content is identical; only
the wrapper each tool expects differs.

## Rules

| # | Rule | Source |
|---|---|---|
| 1 | States what choom is, the absolute workspace path, and that `AGENTS.md` holds the instructions | FR-002 |
| 2 | Restates nothing from `AGENTS.md` — no layout, frontmatter schema, task format, link syntax, command list, or exit codes | FR-003 |
| 3 | At most 20 lines | FR-004 |
| 4 | Carries the generated-by marker, naming choom and saying it is rewritten | FR-005 |
| 5 | Written in full every time; never merged into existing content | FR-006 |
| 6 | The workspace path appears alone on its own line, unquoted | FR-018 |
| 7 | Exactly one such file exists across all assistants at any time | FR-008 |
| 8 | No other file in those directories is read, modified, or deleted | FR-010 |

## The marker

A fixed string — the `Generated by choom` comment — serves two purposes:

1. It satisfies FR-005, telling a user who finds the file that editing it is pointless.
2. It is the precondition for deletion. choom removes a file at one of its own paths **only** when
   the marker is present; otherwise the file is left alone and the caller warns. Overwriting our own
   path needs no check (FR-006 mandates a full rewrite); deletion is irreversible and gets the
   stricter test.

## What a test should assert

- The rendered body contains the workspace path verbatim, including when that path has spaces and
  non-ASCII characters.
- The rendered body contains none of the distinctive strings from `AGENTS.md.tmpl` — for example
  `meetings/YYYY/MM/`, `id: meeting_`, `choom task add`, `Exit codes:`.
- Line count is at most 20.
- The marker is present in both assistants' renderings.
- Rendering is deterministic: the same workspace renders byte-identical output twice (no timestamp,
  no version string, nothing that would make an unchanged re-run rewrite differently).
